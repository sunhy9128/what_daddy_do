# ADR 0001: 功能取舍——主线收敛为「课程 + 工具」，移除社区与 AI 问答

- 日期：2026-09-22
- 状态：已接受

## 背景

项目功能膨胀：19 个工具、5 个 tab、社区 UGC、AI 问答、多张无人消费的数据库表，而开发者只有 1 人、每周预算 ≤10 小时，产品尚无真实用户。继续平摊维护会让主线质量无法达标。

## 决策

1. **主线**：前期只做「课程 + 实用工具」。社区（爸爸帮）与 AI 问答暂缓，等有真实用户反馈后按数据决定是否重建。
2. **移除代码而非隐藏**：community 页面、ai 页面、AIChat、api.ts 的 Community/Knowledge 域、状态层 communityPosts 全部从代码库删除。DB 表保留不删。
3. **砍 5 个工具**：备孕排卵追踪、爸爸情绪自评、妈妈体重记录、护理日志、宝宝睡眠。理由：排卵/体重是妈妈主体场景，与爸爸视角不符；护理/睡眠日志与喂奶计时重叠且是行数大户。
4. **wechat-miniapp 删除**：该目录是没有一行源码的空壳（功能对齐 0%），且个人开发者无 ICP 备案无法上架小程序；主线改为 Expo 单端发 Android 应用市场。
5. **后端收缩**：Supabase 只保留账号 + 任务 + 宝宝档案 + 工具静态表（疫苗/食物安全/待产包/儿保/心理支持）。死表 pregnancy_stages 以 019 迁移删除。

## 理由

- 个人维护带宽是最紧约束，死代码和半成品功能是纯负债。
- 爸爸视角是产品差异化，妈妈主体的工具削弱定位。
- 删除优于隐藏：git 历史可找回，类型检查和重构不再被拖累。

## 后果

- 工具从 19 个减至 14 个，tab 从 5 个减至 4 个（首页/任务/课程/我的）。
- tools/ 从约 10441 行降至约 7000 行。
- 将来若重做社区/AI，应基于届时用户需求重新设计，而不是恢复本次删除的半成品。
- 已进 git 历史的明文密钥（EXPO_TOKEN、Supabase anon key 残留脚本）仍需轮换——删除文件不等于撤销泄露。
